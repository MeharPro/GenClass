## 0. Bottom line

1. **"Better than Jev on every public benchmark" will not happen, on either track, at any size we can train on CPUs.** It is still the right target list: we chase every row and report every loss.
   - The scoreboard has **154 counted benchmarks**: the 131 of `feasibility-targets.md` plus 23 tier-A rows found on 2026-10-03.
   - **56 of the 154 are expected losses on both tracks at every size.** They are world knowledge and multi-step reasoning (MMLU, MMLU-Pro, GPQA, BBH, HellaSwag, WinoGrande, ARC, the exams), multilingual sets, reward-model and PRM suites, ceilings, and sets with no train split where Jev already beats every public specialist.

   Jev is a strong zero-shot model. No public zero-shot model of 1B or less is within 10 points of it on intent, topic or NLI. 5. **Recommended spend:** Azure credits only, $0 on Jev. Core plan: data VM, clean Z-68m, S-68m, S-400m, Qwen3 pilot and all evaluations, at **≈ $2.9–5.1k** and about **6–9 days** wall-clock on the 12-node cluster (§5). **[needs user OK]**.    - "On ~37 of 154 public benchmarks with a published Jev number, one ≤400M supervised model beats Jev's best published score by a statistically clear margin. Where Jev has a 'given train data' number, that is the number it beats. On ~48 more it is within noise."

   - "Far behind on knowledge, reasoning, reward modelling and multilingual sets."

## 1. The scoreboard we will chase

### 1.1 What counts as a target

- **Every row of `jev_published.json` is a target** and appears in `targets.json`. Rows are split by role so the headline numbers are not double-counted:

  | Role | Rows | Meaning |
  |---|---|---|
  | headline | 154 | One row per distinct benchmark: the full-split (tier A) or ≥687-item (tier B) primary metric, in the harness we replicate |
  | s_bar | 10 | Jev **given train data** (few-shot retrieval, dev-tuned thresholds). This is the bar for the S track on that benchmark |
  | secondary | 58 | Same benchmark under another harness or metric on the full split (e.g. Banking77 under DI, DMB, chepyle, laya-ft, morrenhale). Each is run and reported in its own harness |
  | context | 300 | Samples (n ≤ 1,000), small-n pilots, single-author one-offs. Reported in Appendix A, never summed into the headline |
  | composite | 4 | DI index, jev-bench macro, LexGLUE mean, TypeSafe workflow mean |
  | diagnostic | 23 | Not a target: memorisation probes, ECE-only, agentic episodes with n ≤ 100, LLM-judge-labelled sets |

- **The bar.** We claim a **Win** only if ours − Jev > bar (`targets.json` `bar_z` / `bar_s`). The bar is the unpaired significance margin of `feasibility-targets.md` §1.2:
  - √2 × CI half-width where the publisher gives a CI (all 37 Deußer rows);
  - otherwise 1.96·√(2p(1−p)/n).

  Lower-is-better metrics (Brier, RMSE, KL, FNR, false-alarm rate) have bars below Jev. Above the point but below the bar is reported as **Ahead (n.s.)**, not a win.
- **Jev value conflicts.** For the 4 DI rows where the kit fixture and the Space `index.json` disagree (BPoMP .909/.906, POP909 .166/.181, cfcolor .644/.6474, GPQA .786/.7828), the bar uses the **stricter** value.
- **The S bar** is max(Jev zero-shot, Jev given train data) + margin:

  | Benchmark | Jev zero-shot | Jev given train data (row) | S bar |
  |---|---|---|---|

  | UNFAIR-ToS, Deußer | .499 | .748 (T044) | ≈.815 |

## 2. Two tracks and strict test hygiene

### 2.1 Track definitions

| | **Z: zero-shot** | **S: supervised / specialist** |
|---|---|---|
| Benchmark data in training | None, from **any** split, mirror, sibling or derived set of any of the 549 rows' sources | The official **train** split (and validation, for selection) of that benchmark and of every other benchmark. Related public data is allowed |
| Test split | Never touched | Never touched: not for training, selection, calibration, thresholds or template choice |
| Selection | Clean dev set only (§2.3); one checkpoint for every row | That dataset's validation split. Where Jev's eval split *is* validation, a 10% held-out carve of train |
| Calibration | One global temperature file per (kind × K-bucket), fitted on clean dev | Per-dataset temperature and per-label thresholds fitted on validation or held-out train, selected by run config, never by detecting the benchmark. The DI run uses the global file only (DI rule) |
| Model granularity | One checkpoint per size | **S1:** one multi-task checkpoint per size (the headline). **S-spec:** per-benchmark fine-tune from S1, in a separate column. **S-ens:** ensembles, separate column, disclosed |
| Compared against | Jev zero-shot number | max(Jev zero-shot, Jev given train data) |

Rows with no train split are handled as follows:

- **S-cv:** k-fold out-of-fold predictions grouped by source document. Used for SMS spam (Deußer), Arize spam, Cohen ADHD and RiceChem. Shown in a separate S-cv column and never in the S headline.
- **S+gen:** freshly generated items from the benchmark's own generator with new seeds (CLadder, MuSR). Shown separately.
- **Z only:** LLM-AggreFact (the card forbids training), SummEval, the OpenAI moderation eval, HateCheck, the injection corpora that contain deepset train, and TypeSafe evals. The S column shows "Z-only".

### 2.2 Rules that apply to both tracks

1. **No Jev output ever enters training, selection, calibration or distillation.** That covers every per-item Jev file, typed-decisions teacher labels that came from Jev, and registry rule `jev_labelled`.
2. **Test is read once per release.**
   - Each harness runs on test exactly once per checkpoint.
   - Reruns are logged with a reason (crash, adapter bug found on dev), and the first complete run is the one reported.
   - Adapters are debugged on validation or train items only.
3. **Pre-registration.** Before any S or Z training starts we freeze:
   - `targets.json`;
   - this plan;
   - the dev set list;
   - the S allow-list;
   - the decontamination manifests.

   Their sha256 go into `bench/public/PREREG.sha256`, timestamped. `/Users/meharkhanna/jev` is not a git repo, so we cannot tag a commit. **[needs user OK]** to publish the hash early, for example in a GitHub gist, which makes the pre-registration verifiable.
4. **Selection criterion fixed in advance:**
   - Z: mean dev skill over the clean dev set.
   - S: mean validation skill over the S allow-list, equally weighted per dataset.

   Checkpoint averaging is allowed. Choosing per test row is not.
5. **Coverage.** Every suite except Deußer counts refusals as wrong. In Deußer we must answer 100% of rows (truncate mode, disclosed) or report a "missing = wrong" variant beside the published-protocol number.
6. **Templates.** The request bytes are always the harness's own bytes, imported from the pinned harness code. We never paraphrase them.
   - S may train on train-split items rendered in the **harness's** request shape. This is format alignment; Dinah-0 is the precedent. Disclosed.
   - Z may train only on non-benchmark data rendered in those shapes. A shape is not data.

## 4. Model ladder and recipe

### 4.1 Ladder

| Rung | Backbone | Init | Track(s) | Why |
|---|---|---|---|---|
| **Z-68m** | Ettin-encoder-68m + per-option-isolated typed heads (v2 architecture) | Ettin base | Z | Clean zero-shot number, leaderboard checkpoint, parent of S-68m |
| **S-68m** | same | Z-68m | S1 | Cheap: 18–21 S wins at 68m, CPU/Mac-deployable |
| Z-150m | Ettin-150m | Ettin base | Z | Optional. +1 Z win, +9 Z toss-ups over 68m |
| **S-400m** | Ettin-400m | Ettin base (typed format learned inside the 1.3B-token run) | S1 | **Main contender**: 37 W / 48 T |
| S-1b-spec | Ettin-1b | Ettin base, short multi-task warm-up, then specialist fine-tunes | S-spec | Stretch: the 6 rows that only 1b wins (αNLI, STS-B, HelpSteer2 ρ, ESCI, ACOS, ECtHR-B) plus the 1b toss-ups |
| LLM scorer pilot | Qwen3-8B-Base, prefill-only option log-probs, no CoT | – | Z (and S with a BoolQ LoRA) | Only to test whether C-Eval, BoolQ and PubMedQA turn into toss-ups. Reported as a **different system** (`meharsjev-scorer-8b`), never as meharsjev |

What not to build [D]:
- **An 8B decoder reward model.** $2–4.5k for ≤2 toss-ups.
- **A full Qwen3 knowledge pass.** $160–1,320 for an expected 0 wins.
- **A multilingual backbone (mmBERT / AfroXLMR).** It would move only AfriXNLI and SIB-200 to toss-ups at best. Revisit after the core plan.

### 4.2 Recipe

1. **Z-68m.**
   - The v2 recipe on the clean mixture: 1.34B tokens, typed heads, per-option isolation (packing- and order-invariant by construction).
   - Format alignment to the harness request shapes, using non-benchmark data:
     - label as key with `null` value;
     - opaque `option_i` keys with descriptions;
     - empty state with the input in `instructions` (DI);
     - key == value (DMB);
     - object-valued instructions (Deußer, DI ToolRet/BRIGHT).
   - Selection on the clean dev set. One global calibration file.
2. **S1 (68m, 400m).** Multi-task over the S allow-list. Rev-2 mix ≈ 0.77B tokens/epoch (`feasibility-targets.md` §7). One run ≈ 1.3B tokens:
   - ~1.5 epochs of the rev-1 blocks, with small sets upsampled;
   - ~1 epoch of the new legal, safety, intent and grounding blocks;
   - ~0.3B tokens of clean Z-mixture replay to keep zero-shot breadth.
3. **Per-dataset instruction templates.**
   - Every training item of dataset D is rendered in the exact request shape of **every harness that scores D**. Banking77, for example, is rendered in the Deußer `null` labels, the DI `option_i` keys with input-in-instructions, the DMB key = value, the BTZSC hypotheses and the jev-bench shape. Each shape is built by importing the harness's own builder at its pinned commit.
   - Plus 2 paraphrased instruction variants per dataset, to avoid string-memorisation.
   - Templates never come from test items.
4. **Per-dataset calibration (S only).**
   - Temperature per dataset (and per kind for multi-question sets).
   - Per-label thresholds for multi-label noul tasks (GoEmotions, UNFAIR-ToS, AGB-DE, ToxicChat, LexGLUE multi-label). This mirrors the threshold tuning behind Jev's own "given train data" numbers.
   - Fitted on validation, or a 10% train carve where validation is the eval split.
   - Stored as a calibration file chosen by the run config per harness (`--calib s1-perdataset.json`). The server never inspects requests to guess the benchmark.
   - The DI run and the JevBench run use the global file.
5. **Long inputs.**
   - 8k-token context: Ettin native. Truncation (disclosed) is allowed for Deußer, Jevals, DMB, LexGLUE and typed-decisions.
   - DI: refuse beyond the window, with W4 markers. About 1,681 DI rows exceed 8k; they count as wrong.
   - ContractNLI, ECtHR and SCOTUS are where truncation decides the row. Report the number truncated per row.
6. **S-spec (stretch).** From S1, a 0.1–0.3B-token fine-tune per target row on that dataset's train split only. Validation-selected. Reported in its own column.
7. **Ensembles.** Allowed only in an "S-ens" column, disclosed: members, sizes, combination rule chosen on validation. Never in a headline or a DI entry. Not planned in the core budget.
8. **Engine work before any number is valid** (`suite-reproduction-specs.md` §1.2):

   | Item | Requirement |
   |---|---|
   | W1–W2 | `choice`/`confidence`/`score`/`legend` in answers |
   | W3 | leaderboard precision mode (unrounded, or largest-remainder 2-dp) |
   | W4 | refusal bodies carrying the DI capacity markers; status configurable 400/422 |
   | W5 | overflow refuse/truncate switch |
   | W6–W8 | object instructions, empty state, `null` = `""` = key |
   | W9 | calibration file per run config |
   | W10 | model id `meharsjev-*` |
   | W11 | determinism report |
